# Old Picture Art — исправление установщика (версия 3)

## Причина

Ошибка `Не найден конец блока дат афиши` возникает в `apply_verified_fixes.py --check` из-за слишком точного поиска HTML:
старый установщик требовал строку `<span class="now-when afisha-when"></span></p>`.
В уже обновлённом `sitebuild/afisha.py` есть атрибут `role="status"`, поэтому поиск не находил тот же элемент.
Это ошибка установщика, а не повреждение афиши. Команда `--check` ничего не меняла.

## Установка

1. Сохраните рабочую копию проекта либо сделайте резервную копию.
2. Распакуйте архив в `D:\Code\oldpictureart_site` **с заменой** двух файлов:
   - `apply_verified_fixes.py`
   - `test_verified_fixes.py`
   **Не удаляйте** существующие `afisha.json`, `museum_overrides.json`, `.env`, `docs/`, `sitebuild/`, `.git/`.
3. Выполните из PowerShell в корне проекта:

```powershell
python apply_verified_fixes.py --check
python test_verified_fixes.py
python apply_verified_fixes.py --apply
python -m compileall -q sitebuild
python tests/test_afisha.py
python tests/test_safety.py
python rebuild_pages.py --offline
```

Если проверки прошли, можно выполнить обычную сборку `python build_site.py`.

## Что исправлено

- Функция `afisha_item` ищется по структуре, а не по одному неизменяемому HTML-фрагменту.
- Варианты `afisha-when` с `role="status"` и дополнительными атрибутами поддерживаются.
- Добавление адресов и подавление ложного `404` только для подтверждённого URL «Русский Париж» сохраняются из прежнего пакета.
- Неизвестная структура по-прежнему приводит к **отказу без записи**; установщик не пытается угадать, как изменить неизвестный код.
- При `--apply` создаются резервные копии редактируемых файлов в `output/backups/`.
- Никакие файлы в GitHub архив не меняет. При успешной обычной сборке работает штатный механизм публикации.

повторное применение патча и конфликт при `non-fast-forward` на локальном Git.

Если `--check` по-прежнему сообщает о незнакомой структуре `afisha_item`, не запускайте `--apply` и пришлите `sitebuild/afisha.py` и полный вывод `--check`: это означает, что локальный файл отличается и от двух проверенных вариантов.
