# Old Picture Art — девять фильтров афиши

**Исходный проект:** `DenchesT/Site-Oldpictureart`, ветка `main`, проверенная ревизия `7c46b1186afb245609be238030b8001649b93aa4` (30.10.2026).

Этот архив содержит **код установки патча**, а не всю папку `docs` с картинами. Он обновляет исходный генератор афиши и CSS непосредственно в вашем проекте. Изображения и `afisha.json` не заменяются. Сам сайт на GitHub не менялся.

## Реализовано

1. **Статус:** «Сейчас и скоро» (как раньше, по умолчанию), «Все периоды», «Идут сейчас», «Скоро откроются», «Архив». Перемещение определяется датой в браузере, без ежедневной пересборки.
2. **Закрытие:** в ближайшие 7 / 30 / 90 дней. Выбор автоматически переключает статус на действующие выставки.
3. **Открытие:** в ближайшие 7 / 30 / 90 дней. Выбор автоматически переключает статус на будущие выставки.
4. **Художник:** поиск по имени в `artists`, названии и заметке выставки. Там, где художники не указаны в этих данных, поиск не сможет их определить без пополнения `afisha.json`.
5. **Музей:** раскрывающийся список названий площадок (`venue` в `afisha.json`).
6. **Поиск:** название, музей, город, страна, оригинальное название и заметка.
7. **Год архива:** по году закрытия выставки; доступен при выборе «Архив».
8. **Сортировка:** дата события, открытие, закрытие, название и музей.
9. **Избранное:** звёздочка у выставки и «Только избранные». Хранится в `localStorage` конкретного браузера; **между устройствами не синхронизируется**.

Также: кнопка сброса фильтров; восстановление части настроек после перезагрузки; ссылки на архивные записи с правильным переключением вкладок; архивные посещения связываются с историческими выставками. Карту и блок на главной по-прежнему заполняют **только актуальные и ближайшие** выставки. Завершившиеся выставки не включаются в SEO-разметку как действующие события.

Дизайн сохраняется: прежние фон, цветовая система, типографика и структура карточек. Добавляются только аккуратные элементы управления на основе существующих стилей.

## Установка (Windows / PowerShell)

1. Сохраните изменения в Git (или сделайте резервную копию). Убедитесь, что корень проекта — например, `D:\Code\oldpictureart_site` — содержит `sitebuild/afisha.py` и `afisha.json`.
2. Распакуйте **содержимое ZIP** в корень проекта. Новые файлы `apply_afisha_filters.py`, `test_installer.py` и `tests/test_afisha_filters_new.py` добавятся рядом с кодом.
3. Откройте PowerShell из корня проекта и выполните:

```powershell
python apply_afisha_filters.py --check
python apply_afisha_filters.py
python tests/test_afisha_filters_new.py
python tests/test_afisha.py
python rebuild_pages.py --offline
node tests/test_afisha.js
```

4. Откройте `docs/afisha.html` в браузере. Проверьте «Архив», «Идут сейчас», поиск и избранное. Для проверки адаптивности используйте режим телефона в инструментах разработчика.
5. Посмотрите `git diff` и только после этого отправляйте изменения в GitHub. **Файлы `.bak-...` не добавляйте в коммит** — это локальные резервные копии.

> Рекомендуемый Python для существующей CI-сборки — 3.12. Для полноценной проверки браузерных тестов нужны Node.js, Playwright и Chromium из зависимостей проекта.

## Что обновляется

- `sitebuild/afisha.py` — генерация исторических и будущих записей, фильтры, скрипт, избранное, сортировка.
- `docs/style.css` — только дополнительные правила для элементов фильтрации.
- `tests/test_afisha.py` — адаптация старых ожиданий к архиву и дополнительные проверки разметки.
- `tests/test_afisha.js` — адаптация сценариев и тестирование новых фильтров.
- `tests/test_afisha_filters_new.py` — отдельный офлайн smoke-тест (новый файл).

Установщик сначала проверяет **все ожидаемые фрагменты** и `ast.parse()` итогового Python-кода, и только потом начинает запись. При неизвестной версии он остановится, ничего не меняя. Повторное применение не должно дублировать изменения. Перед заменой создаются соседние копии `.bak-<дата>`.

## Важно про архив

**Не удаляйте завершившиеся выставки из `afisha.json`**, иначе они исчезнут из архива. Раньше лог рекомендовал удалять записи старше 14 дней; теперь формулировка изменяется. Выставки, уже удалённые из файла до установки, не восстановятся автоматически.

## Проверки, выполненные при подготовке ZIP

- Python-файлы установщика и тестов компилируются.
- Тест установщика проверяет **32 точечных замены** кода, три замены Python-тестов, пять изменений браузерных тестов и шесть JavaScript-фрагментов через `node --check`.
- **Ограничение:** полный код репозитория не был доступен в локальном исполнении без сетевого доступа. Поэтому реальная пересборка сайта, прогон Playwright и применимость к вашей рабочей копии **должны быть подтверждены командами выше**. Не публикуйте архив автоматически без этих проверок.

При несовпадении установленной версии выполните `git status` и передайте текст ошибки установщика; не заставляйте его применять изменения через отключение проверки.
