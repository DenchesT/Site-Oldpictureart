# Исправления предупреждений сборки OldPictureArt — 29.10.2026

**Основание:** лог запуска `build_site.py` из Python 3.15 от 29 октября 2026 года. Репозиторий: `DenchesT/Site-Oldpictureart`.

## Что исправлено

1. **Ошибочная метка частной коллекции.** В `museum_overrides.json` добавляется `"Частная коллекция, Фонд Константина Кузнецова, Москва": {"skip": true}`. Геокодер больше не подставляет вместо коллекции ювелирный магазин на Волхонке. Сведения о картинах и страницах коллекции **не удаляются**; без проверенного публичного адреса правильнее не показывать метку.
2. **Лишнее предупреждение об отсутствии адреса** для места, намеренно скрытого с карты. В `sitebuild/places.py` список таких мест теперь проверяет `skip`.
3. **Две ссылки афиши:** старые URL выставок «Ева Гонсалес» и «Сокровища Саньсиндуя и Цзиньша» заменяются прямыми официальными страницами на сайтах Petit Palais и Guimet. Остальные записи афиши не меняются.
4. **Ошибка `FakeTLSStreamWriter.wait_closed` при отключении от Telegram:** новый адаптер `sitebuild/telethon_compat.py` аккуратно делегирует `wait_closed()` базовому потоку. Устанавливается только когда у класса нет метода. Не меняет настройки прокси, шифрование и авторизацию.
5. **Номер телефона в логах:** вместо его полного вывода отображается нейтральное сообщение. Проверьте также, не попал ли старый журнал в публичную Git-историю.
6. **CI:** добавлен запуск офлайн-регрессий.

## Установка (Windows / PowerShell)

1. Сделайте резервную копию или Git-коммит **до установки**. Не запускайте на грязном дереве без просмотра `git status`.
2. Распакуйте ZIP в **корень** репозитория, например `D:\Code\oldpictureart_site`, сохраняя структуру папок. В архиве только новые файлы — текущие JSON не затираются.
3. Из этого каталога запустите:

```powershell
python apply_log_fixes.py --dry-run
python apply_log_fixes.py
python tests/test_log_fixes.py
python tests/test_safety.py
python rebuild_pages.py --offline
```

`apply_log_fixes.py` меняет только `afisha.json`, `museum_overrides.json`, `sitebuild/places.py`, `sitebuild/telegram.py`, `.github/workflows/tests.yml`. Для каждого изменённого файла создаёт `.bak` рядом с оригиналом. Он безопасен при повторном запуске: уже внесённые правки не накладываются повторно. Если исходный код отличается от ожидаемого, изменения **не выполняются** (ничего не перезаписывается). Для отката используйте Git или `.bak`.

Для совместимости с устаревшим FakeTLS предпочтительнее использовать Python 3.12. Если он установлен, можно создать отдельное окружение (один раз):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tests/test_log_fixes.py
.\.venv\Scripts\python.exe rebuild_pages.py --offline
```

Не нужно одновременно запускать сборщик разными версиями Python с одними и теми же session-файлами.

Посмотрите результаты `git diff` и карту `docs/museums.html`, прежде чем публиковать. Локальная пересборка `--offline` не требует Telegram, а команда в этом архиве **не выполняет git push**. Убедитесь, что сборка действительно пишет карту без предупреждения об ошибочной метке.

## Что НЕ исправлено и почему

- **`cryptg module not installed and libssl not found`** — это предупреждение об отсутствии ускорения шифрования, а не сбой TLS/подключения: в вашем логе соединение с Telegram успешно. Вместо установки непроверенного бинарного модуля под Python 3.15 рекомендуем Python **3.12** в отдельном окружении (эта версия закреплена в GitHub Actions). Запускайте весь проект одним интерпретатором.
- **`python-socks is not installed`** — Telethon выводит общее предупреждение, хотя установленный транспорт FakeTLS действительно соединился с прокси. Не добавляем `python-socks` только ради скрытия сообщения: другой транспорт может изменить работу прокси. После смены версии Python повторно проверьте подключение.
- **«Русский Париж. 1814–1914»** — официальный URL `https://www.domrz.ru/exhibition/70568_russkiy_parizh_1814_1914/` подтверждается открытой страницей музея, поэтому ссылка не заменена. Вероятнее всего, ваш локальный чекер получает другой HTTP-ответ или показывает старый недельный кэш `afisha_links.json`. Это нужно перепроверить из того же окружения, где запускается сборка. Не стоит автоматически объявлять настоящую официальную страницу нерабочей.
- **~59 секунд на автоматический коммит** — лог не показывает, какой именно этап медленный (Git, файловая система, антивирус, LFS или хуки). Без замеров нельзя безопасно «ускорять» публикацию.
