# Old Picture Art — облачная синхронизация арт-паспорта

**Дата:** 8 ноября 2026. **Репозиторий:** `DenchesT/Site-Oldpictureart` (`main`).

Пакет **ничего не публикует** и **не выполняет git commit/push**. Это локальный набор файлов и двух проверяемых установщиков. Подготовлен на основе уже существующей авторизации Яндекс ID / VK ID и таблицы лайков в Yandex Cloud/YDB.

## Что синхронизируется

| Данные | Где хранятся у вошедшего посетителя |
|---|---|
| Любимые картины и любимые выставки | **Как прежде:** существующая `likes` в YDB |
| Любимые художники | Новая приватная таблица `passport` в той же YDB |
| Музеи, которые отметил посетитель | `passport` |
| Картины, которые посетитель видел вживую | `passport` |
| Названия и содержимое личных коллекций | `passport` |
| Личная статистика | Рассчитывается в браузере из синхронизированных данных |

Никакие посты дневника автора (`visits.html`) автоматически не становятся отметками посетителей. У гостя данные живут только в его браузере. **После входа** текущий гостевой паспорт можно один раз автоматически перенести в аккаунт. Данные разных Яндекс/VK аккаунтов не смешиваются.

Все изменения сперва сохраняются локально; без сети браузер хранит очередь изменений и попробует отправить её при следующем открытии, возврате во вкладку или появлении подключения. Новые элементы появляются на втором устройстве при открытии/возврате на сайт, а не push-уведомлением. **Если одновременно править одну коллекцию с двух устройств, побеждает последнее успешно отправленное изменение этой коллекции**; для разных коллекций и отметок обновления независимы.

## Порядок установки — важно

1. **Сделайте резервную копию своих изменений** (`git status --short`), если работаете в папке проекта.
2. Распакуйте **содержимое ZIP в корень** `D:\Code\oldpictureart_site`, сохраняя вложенные папки и заменяя одноимённые файлы из предыдущего ZIP арт-паспорта. Внутри — новые версии JS и генератора и скрипт установщика.
3. Если самый первый арт-паспорт **ещё не установлен**, выполните сначала `python apply_art_passport.py --check`, затем `python apply_art_passport.py --apply`. Если установлен, этот шаг можно пропустить.
4. Установите облачное расширение (проверка не меняет файлы):

```powershell
cd D:\Code\oldpictureart_site
python apply_passport_cloud_sync.py --check
python apply_passport_cloud_sync.py --apply
python -m compileall -q sitebuild cloud/auth
node tests/test_passport_actions.js
node tests/test_passport_cloud.js
python -m unittest tests.test_passport_sync_installer tests.test_passport_cloud_backend tests.test_passport
python rebuild_pages.py --offline
```

Перед `--apply` скрипт проверяет исходники и Python-синтаксис. Он делает резервную копию пяти файлов в **соседней папке** `oldpictureart_site_backup_passport_cloud_...`; не пишет в GitHub. При несовпадении участков кода останавливается без изменения файлов.

5. **Создайте новую таблицу в текущей YDB**, в которой уже хранится `likes`. Откройте Yandex Cloud → YDB → ваша база → SQL-запросы и выполните **один раз** содержимое `cloud/auth/passport_table.sql`:

```sql
CREATE TABLE passport (
    user_id Utf8,
    entry_key Utf8,
    payload Utf8,
    updated_at Timestamp,
    PRIMARY KEY (user_id, entry_key)
);
```

**Таблицу `likes` не меняйте.** В ней остаются старые лайки и избранные выставки. Не выполняйте `DROP TABLE`, не удаляйте БД и не создавайте ещё одну отдельную базу.

6. **Обновите существующую Cloud Function `opa-auth`**: возьмите обновлённый `cloud/auth/index.py` из вашей папки **после** выполнения установщика и замените этим кодом `index.py` в редакторе уже существующей функции. Используйте ту же точку входа `index.handler`, тот же сервисный аккаунт и **те же** переменные окружения; особенно не меняйте `SESSION_SECRET`, иначе придётся снова входить. Сохраните/разверните новую версию. Создавать ещё одну функцию/новый URL не нужно.
7. Только после создания таблицы и обновления функции публикуйте статические файлы сайта: `git status`, затем ваш обычный commit/push. Не запускайте `python build_site.py` без `--no-push` для проверки, поскольку у него есть автопубликация; используйте `rebuild_pages.py --offline`.

**Без шагов 5–6** интерфейс будет работать в браузере, но сервер будет отвечать ошибкой на `passport_sync` и новые данные **не смогут** синхронизироваться. Плашка в паспорте покажет ошибку, локальные отметки сохранятся для повторной отправки.

## Что изменит установщик

- `cloud/auth/index.py` — приватный API `passport_sync`, проверка формата ключей и размеров, чтение/изменение строк `passport`, очистка паспорта при удалении облачных данных аккаунта.
- `sitebuild/artists.py`, `sitebuild/museums.py` — подключение существующего `CLOUD_JS` на страницах с кнопками «Любимый художник» / «Я был в музее», чтобы синхронизация работала прямо там.
- `sitebuild/static.py` — уточнение раздела конфиденциальности: теперь перечислены все новые категории облачных данных.
- `site_common.py` — ссылка на паспорт в профиле и уточнение описаний синхронизации / удаления облачных данных.
- `docs/passport-actions.js`, `docs/passport.js` — пакет уже содержит обновлённые файлы, они устанавливаются при распаковке (не через Python-скрипт).
- `sitebuild/passport.py` — обновлённый текст состояния синхронизации на самой странице (переходит в HTML при офлайн-сборке).

Два скрипта установки (`apply_art_passport.py`, `apply_passport_cloud_sync.py`) повторно запускать после установки не требуется. Новые персональные сведения **не сохраняются в файлы репозитория**: в GitHub попадает только код и статическая оболочка паспорта.

## Проверка после обновления облака и публикации

1. Войти на сайте через Яндекс ID или VK ID, открыть `passport.html`. Проверить статус «Арт-паспорт синхронизирован».
2. Отметить любимого художника и музей, увидеть оригинал, создать коллекцию, добавить работу.
3. Войти **под тем же аккаунтом** во втором браузере / телефоне, открыть паспорт: отметки и названия подборок должны появиться.
4. Удалить отметку на втором устройстве, вернуться к первому: она исчезнет при синхронизации.
5. Отключить интернет, добавить отметку, включить интернет и снова открыть паспорт: изменения должны загрузиться.
6. Проверить, что старые лайки картин и избранные выставки работают и синхронизируются как прежде.

**Удаление данных.** Кнопка «Удалить мои данные из облака» в профиле теперь очищает не только лайки, но и новую таблицу паспорта **для этого аккаунта**. Файлы JSON и данные в старых браузерах автоматически не уничтожаются; после повторного входа авторитетное облачное состояние их обновит. Для резервной копии по-прежнему доступен экспорт JSON.

**Конфиденциальность.** Названия любимых музеев, отметки посещения и подборки — личные данные, доступные через авторизованный API только соответствующему аккаунту. У владельца базы YDB остаётся административный доступ. Обновите опубликованную страницу `privacy.html` вместе с сайтом.

**Ограничения:** без новой таблицы/деплоя синхронизации не будет; текущая реализация не поддерживает push-уведомления и не разрешает совместное конкурентное редактирование *одной* коллекции с двух устройств в реальном времени. При недоступности localStorage (например, ограниченный режим приватности) локальное сохранение может не работать.
