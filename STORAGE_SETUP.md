# Оригиналы в облачное хранилище — как завести

Сайт почти упёрся в предел GitHub Pages: `docs/images` весит около 1 ГБ,
а больше 1 ГБ Pages не публикует. Три четверти этого веса — оригиналы
для скачивания (файлы `-hires-`). Их можно вынести в **Yandex Object
Storage** — в тот же Yandex Cloud, где уже работает вход на сайт. Сайт
похудеет примерно вчетверо, а кнопка «Скачать картину» и лупа продолжат
работать как прежде.

Займёт полчаса, из них большая часть — сама выгрузка.

**Сколько стоит.** Первый гигабайт хранения, первые 100 ГБ исходящего
трафика и первые 100 000 скачиваний в месяц бесплатны. Сейчас оригиналов
около 770 МБ — это целиком влезает в бесплатную часть; дальше за каждый
лишний гигабайт в месяц будут копейки.

---

## 1. Бакет (5 минут)

Бакет — это «папка» в хранилище, куда лягут оригиналы.

1. Откройте **https://console.yandex.cloud** и выберите тот же каталог,
   где уже живёт функция входа (`opa-auth`) и база `opa-likes`.
   Платёжный аккаунт у вас уже есть — отдельно заводить ничего не нужно.
2. В списке сервисов слева — **Object Storage** (если его не видно, найдите
   поиском по «Object Storage» или откройте «Все сервисы»).
3. Справа вверху — **«Создать бакет»**.
4. Заполните форму:

   | Поле | Что поставить |
   |---|---|
   | **Имя** | `oldpictureart` |
   | Метки | ничего |
   | **Максимальный размер** | можно не ограничивать, можно поставить 5 ГБ |
   | **Чтение объектов** | **Для всех** — иначе посетитель не сможет скачать картину |
   | **Получение списка объектов** | С авторизацией |
   | **Чтение настроек бакета** | С авторизацией |
   | **Класс хранилища** | Стандартное |
   | Ключ KMS | ничего |

   Про имя: только строчная латиница, цифры и дефис, от 3 до 63 знаков,
   без точек (с точкой в имени бакет по умолчанию работает только по
   HTTP, а сайт открыт по HTTPS). Имена общие на весь Yandex Cloud — если
   `oldpictureart` занято, возьмите `oldpictureart-hires` или
   `oldpictureart-files` и дальше везде пишите его.

5. **«Создать бакет»** внизу формы.

Проверка: бакет появился в списке, у него «Чтение объектов — Для всех».
Если ошиблись — откройте бакет → «Настройки» → «Общие» и поправьте там.
Адрес бакета для сайта: `https://storage.yandexcloud.net/oldpictureart`
(с вашим именем) — он понадобится в шаге 3.

## 2. Ключ для выгрузки (5 минут)

1. **Identity and Access Management** → «Создать сервисный аккаунт»,
   имя `opa-storage`, роль **`storage.uploader`** — она позволяет класть
   файлы, но не удалять их.
2. Откройте аккаунт → «Создать новый ключ» → **«Создать статический ключ
   доступа»**. Выпишите **идентификатор ключа** и **секретный ключ**:
   секрет показывается один раз.
3. Допишите в `.env` рядом с ключами Телеграма:

   ```
   S3_KEY_ID=идентификатор ключа
   S3_SECRET=секретный ключ
   ```

   `.env` в репозиторий не попадает — секрет останется у вас.

## 3. Сайт (1 минута)

В `site_common.py`:

```python
HIRES_BASE_URL = "https://storage.yandexcloud.net/oldpictureart"
```

(своё имя бакета, без косой черты в конце).

Модуль `boto3` сборка поставит сама при следующем запуске
`build_site.py`. Если хочется начать раньше — `pip install boto3`.

## 4. Выгрузка (15–30 минут)

```bash
python hires_store.py            # отчёт: сколько и чего уедет — ничего не меняет
python hires_store.py --upload   # выгрузить
```

Скрипт кладёт каждый оригинал в бакет по тому же пути, что и на сайте
(`images/…-hires-1.jpg`), ставит ему заголовок «скачать под именем
“Художник — Название, год.jpg”», сверяет размер загруженного и только
потом переносит локальный файл из `docs/images` в папку **`hires/`** —
это ваш архив оригиналов. На сайт и в репозиторий он не попадает, но
не удаляйте его: это единственная копия у вас на диске.

Оборвалась связь — просто запустите `--upload` ещё раз: доехавшее он
пропустит, недоехавшее дольёт.

В конце скрипт сам проверит, открывается ли файл без ключа. Если нет —
в бакете не открыто «Чтение объектов — Для всех» (шаг 1).

## 5. Пересборка и push

```bash
python rebuild_pages.py
```

Откройте любую картину и нажмите «Скачать»: адрес должен начинаться
с `https://storage.yandexcloud.net/…`, а файл — сохраниться под
названием картины. Потом push — **вместе с удалениями** из
`docs/images` (в GitHub Desktop они видны как удалённые файлы; в
командной строке — `git add -A docs`).

## Дальше само

Новые посты `build_site.py` выгружает сам: скачал оригинал из канала,
сделал копию для лупы, отправил в хранилище, перенёс в `hires/`. Если
хранилище не ответило или ключей нет, оригинал остаётся в
`docs/images`, ссылка на странице — локальной, и ничего не ломается;
в логе будет строка, чего не хватило. Страницы всегда ведут туда, где
файл лежит на самом деле.

## Если что-то не так

- **«Скачать» открывает картинку, а не сохраняет** — файл выгружен без
  заголовка (например, руками через консоль). Перезалейте:
  `python hires_store.py --upload --force`.
- **403 при скачивании** — в бакете «Чтение объектов» не «Для всех» (шаг 1).
- **`AccessDenied` при выгрузке** — у сервисного аккаунта нет роли
  `storage.uploader` или ключ вписан с ошибкой.
- **Хочу вернуть всё как было** — `HIRES_BASE_URL = ""`, файлы из
  `hires/` обратно в `docs/images`, `python rebuild_pages.py`.
