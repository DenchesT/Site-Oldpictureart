# Возвращена автоматическая отправка в GitHub

Установка: сохраните открытые файлы VS Code, сделайте резервную копию,
распакуйте ZIP в корень существующего проекта с заменой файлов, сохранив
папки sitebuild/, tests/ и .github/. Не распаковывайте в отдельную подпапку.
Затем запускайте build_site.py привычной кнопкой или командой из корня проекта.
Ручные git add / commit / push для установки этого исправления НЕ нужны.
Скрипт сам включит новые файлы и изменения исходников в следующий коммит.

Поведение:
  собрать страницы -> автоматически добавить изменения -> commit -> push
  GitHub Actions -> тесты на GitHub

Локальные тесты НЕ вызываются. Node.js, npm и Chromium для обычного запуска
сборщика на компьютере не требуются. Проверка наличия Python-зависимостей,
предупреждения о данных и сетевые операции самой сборки остаются.

Что исправлено:
- Убран запрет на автоматический коммит измененных исходников.
- Уже подготовленные обычные изменения в Git index не блокируют публикацию.
- Автоматически отправляются код, workflow, package.json, package-lock.json,
  метаданные и страницы, если они не исключены правилами ниже.
- Учитывается .gitignore для новых файлов; .env, .env.*, файлы Telegram-сессий,
  *.pem, *.key, *.secret, *.bak, *.tmp, *.zip и окружения/кэши не добавляются.
  Это фильтрация по именам, а НЕ поиск секретов внутри произвольного кода.
- Если исключенный файл уже вручную staged, отправка остановится с объяснением,
  а не опубликует его. Обычные изменения кода больше не требуют ручного коммита.
- Файлы сессий и .env не удаляются с диска.
- --no-push сохраняется для сборки без Git и IndexNow.
- Ошибки Git показывают текст stderr. Force push и автоматический reset не используются.
- Отсутствие новых изменений не мешает повторить push ранее созданного коммита.

Состав (полные заменяемые файлы):
- build_site.py
- sitebuild/safety.py
- tests/test_safety.py (обновлены проверки автоматического коммита исходников)
- .github/workflows/tests.yml (тесты на push, pull_request, ручной запуск)

Предыдущий исправленный sitebuild/text.py оставьте на месте: этот ZIP его не меняет.
Ваши обновленные package.json/package-lock.json также не заменяются.

Проверка архива:
Синтаксис трех Python-файлов проверен. В среде подготовки выполнены 16 тестов,
включая реальный git add/commit во временных локальных репозиториях. Успешны:
автоматический коммит исходников вместе со страницами; принятие staged-кода;
добавление workflow; удаление файлов; исключения; отсутствие локального запуска
тестов; сохранение JSON и резервной копии. Git push подменялся, сетевых
отправок в репозиторий пользователя не выполнялось.
Полный сайт, Telegram, Playwright и GitHub Actions здесь не запускались.

Важно:
- Две известные проблемы данных карты/частных собраний не исправляются и
  не скрываются. Они могут оставаться красными в GitHub Actions.
- Workflow не меняет настройки GitHub Pages и не связывает деплой с успехом
  тестов. Здесь восстановлен ваш прежний процесс отправки, а не новая схема Pages.
- Реальные ошибки генерации, сети, аутентификации и git push по-прежнему
  могут остановить процесс. Ручного коммита обычного кода скрипт не требует.
- Все обычные неигнорируемые изменения проекта включаются автоматически:
  не храните незавершенные приватные файлы в публичном checkout без .gitignore.
