# Site-Oldpictureart

Статический сайт-галерея картин, который собирается из постов Telegram-канала
[@oldpictureart](https://t.me/oldpictureart). Готовые страницы лежат в `docs/`
и публикуются через GitHub Pages.

## Что где

| Файл | Зачем |
|---|---|
| `build_site.py` | Основной сборщик: забирает новые посты из Telegram, качает картинки, генерирует страницы картин, теги, главную, sitemap, RSS, манифест |
| `rebuild_pages.py` | Пересборка всех страниц из `posts_meta.json` **без Telegram** — когда правится только вёрстка |
| `site_common.py` | Общий `<head>`, бутстрап темы и общие скрипты для всех генераторов |
| `generate_quiz.py` | Страница квиза |
| `generate_timeline.py` | Страница таймлайна |
| `generate_map.py` | Карта музеев: координаты ищутся в Wikidata и OpenStreetMap, кэш в `museum_coordinates.json` |
| `museum_overrides.json` | Ручной справочник музеев — что искать и что не показывать на карте |
| `docs/style.css` | Все стили сайта: переменные темы, типографика, компоненты |
| `posts_meta.json` | База постов: художник, название, музей, техника, файлы картинок |

## Страницы сайта

| Адрес | Что это |
|---|---|
| `index.html` | Опись собрания: поиск, фильтры по годам, художникам и техникам, две раскладки |
| `<дата>-<художник>.html` | Страница работы: изображение, сведения, происхождение, «рядом в собрании» |
| `artist-<художник>.html` | Все работы одного автора с годами и собраниями — по странице на каждого |
| `ukazatel.html` | Указатель: художники, собрания, материал и техника по алфавиту |
| `stats.html` | Статистика собрания: десятилетия, авторы, собрания, города, материал, техника |
| `museums.html` | Карта музеев со списком |
| `tag-<тег>.html` | Подборка по тегу |
| `quiz.html`, `timeline.html` | Квиз и таймлайн |


## Запуск

```bash
# полная сборка с забором новых постов (нужен .env)
python build_site.py

# только пересобрать HTML из уже скачанных данных
python rebuild_pages.py

# то же, но не трогать карту (не ходить в интернет за координатами)
python rebuild_pages.py --no-map

# заново поискать музеи, которые раньше не нашлись
python generate_map.py --regeocode

# собрать карту только по готовым координатам, в сеть не ходить
python rebuild_pages.py --no-geocode
```

## Уборка картинок

Сайт вырос до 1,2 ГБ при пределе GitHub Pages в 1 ГБ. Больше половины веса
оказалось файлами, на которые не ссылается ни один пост и ни одна страница:
остатки переименованных и удалённых записей.

```bash
python optimize_images.py            # только отчёт, ничего не меняет
python optimize_images.py --apply    # выполнить
python optimize_images.py --apply --keep   # сложить лишнее в docs/_unused
```

Скрипт **не трогает оригиналы** (файлы `-hires-`): их отдаёт кнопка
«Скачать картину», поэтому они остаются такими, какими были. Уменьшаются
только миниатюры — они показываются шириной около 130 пикселей, а лежали
шириной до 1200.

Запускать после сборки, чтобы страницы в `docs/` были свежими.

## Знак сайта

Один знак на всё — вкладку браузера, плитку на телефоне и значок рядом
с названием в шапке: пейзаж в раме, цвета те же, что у сайта. Он описан
в `site_common.py` функцией `mark_svg()` и рисуется примитивами, поэтому
`generate_icons()` в `build_site.py` повторяет ту же фигуру растром:

| Файл | Для чего |
|---|---|
| `docs/favicon.svg` | вкладка в современных браузерах, пишется всегда |
| `docs/favicon.ico` | 16, 32 и 48 пикселей для старых браузеров и закладок |
| `docs/apple-touch-icon.png` | значок на домашнем экране iPhone, 180 пикселей |
| `docs/images/icon-192.png`, `icon-512.png` | манифест, установка как приложения |
| `…-maskable.png` | то же для Android: там края обрезаются, поэтому знак ужат внутрь |

Растровые файлы обновляются при сборке и требуют Pillow. Без него
перезаписывается только `favicon.svg`, остальные остаются прежними.

## Лупа

Клик по картине открывает полноэкранный просмотр: колесо и щипок увеличивают,
перетаскивание двигает, двойной щелчок показывает во всю величину, Esc
закрывает. Сначала показывается та же картинка, что уже на странице (она в
кэше, поэтому открывается мгновенно), следом подгружается оригинал из
`hires` и подменяется без рывка.

Ссылка на файл оригинала в разметке остаётся настоящей: без JavaScript
и по Ctrl+клик браузер откроет его как раньше.

## Карта музеев

Метка — музейная этикетка: карточка с числом работ на тонкой ножке, точка ножки
стоит ровно на музее. Близкие метки собираются в стопку карточек с числом музеев
(Leaflet.markercluster) и расходятся при приближении, поэтому четыре парижских
музея больше не сливаются в одно пятно. Цвета метки взяты из переменных сайта,
так что в тёмной теме они перекрашиваются вместе со всем остальным.

Координаты ищутся по цепочке: `museum_overrides.json` → Wikidata → OpenStreetMap →
город или страна из названия. Wikidata стоит первой, потому что знает русские
названия зарубежных музеев, а OpenStreetMap — нет. Каждая находка сверяется с
городом из названия музея: если точка оказалась дальше 100 км, она отбрасывается
и пробуется следующий способ. Без этой проверки Метрополитен-музей стоял
в Бангкоке, а Музей Гетти — на заправке в Коннектикуте.

Найденные координаты складываются в `museum_coordinates.json` и при следующих
запусках берутся оттуда — в сеть скрипт не ходит вообще. Перепоиск случается
только в трёх случаях: появился новый музей, вы поменяли подсказку в
`museum_overrides.json`, или запуск был с `--regeocode`.

Если музей не нашёлся, `generate_map.py` в конце лога печатает готовые строки
для вставки в `museum_overrides.json`. Три формы записи:

```json
"Музей Фабра, Монпелье": {
  "query":   "Musée Fabre",
  "address": "39 boulevard Bonne Nouvelle, Montpellier",
  "site":    "https://museefabre.montpellier3m.fr"
},
"Мой музей, Город":       {"lat": 48.8606, "lon": 2.3376},
"Частная коллекция, США": {"skip": true}
```

| Поле | Что делает |
|---|---|
| `address` | Почтовый адрес. Показывается в карточке, участвует в поиске и спрашивается у геокодера первым — по улице и дому метка ставится точнее, чем по названию музея |
| `site` | Официальный сайт, ссылкой в карточке |
| `query` | Искать по другой строке, обычно по названию на родном языке |
| `lat` / `lon` | Готовые координаты, ничего не искать |
| `skip` | Не ставить метку (музей останется в списке под картой) |

Названия слева должны дословно совпадать с полем `museum` в `posts_meta.json`.

Адрес пишите в виде «улица и дом, город» на языке страны — так его разбирает
геокодер и так он читается в карточке. Почтовый индекс не нужен.

Если поменять `address` или `query`, координаты этого музея будут найдены
заново — остальных это не коснётся. Если новый поиск ничего не дал или
интернета нет, прежняя метка сохраняется: потерять её хуже, чем показать
по старым данным. Если же новая точка оказалась дальше 50 км от прежней,
в логе появится предупреждение: улицы и площади с одинаковыми названиями
есть в разных городах, и такой прыжок обычно значит, что нашлась не та.

На Windows: `update.bat` — полная сборка, `rebuild.bat` — только пересборка страниц.

## Поиск

На страницах работ стоит разметка Schema.org `VisualArtwork` — автор, год,
материал, техника, размер и собрание в виде, который понимают поисковики.
Заголовок вкладки собирается из русского названия и фамилии автора и не
длиннее 70 знаков, иначе выдача обрезает его на полуслове. `robots.txt`
со ссылкой на `sitemap.xml` создаётся при сборке.

Правила безопасности Firestore для лайков — в `FIRESTORE.md`.

## Канал

Собрание растёт из телеграм-канала [@oldpictureart](https://t.me/oldpictureart).
Ссылка на него стоит в подвале каждой страницы (`site_footer()` в
`site_common.py`) и отдельным пунктом в сайдбаре главной. Адрес задан
константой `TELEGRAM_URL` — менять только там.

## Оформление

Сайт оформлен как каталог собрания. Записи пронумерованы по хронологии
создания работ — номер закреплён за картиной навсегда и не меняется
при сортировке. Сведения о работе (год, материал, техника, размер) везде
выровнены в таблицу и набраны моноширинным шрифтом.

Шрифты: **Old Standard TT** для текста, **IBM Plex Mono** для данных
и служебных подписей. Оба с кириллицей, подключаются в `site_common.py`.

Цвета заданы переменными в начале `docs/style.css` — отдельно для светлой
темы (`:root`) и тёмной (`[data-theme="dark"]`). Менять цвет нужно только там:
компоненты обращаются к переменным и нигде не содержат цвета напрямую.

На главной и на страницах тегов один и тот же список умеет показываться
двумя способами — описью и плитками. Разметка при этом одна, вид задаёт
класс `list` на контейнере `.grid`, поэтому поиск и фильтры от переключения
не зависят. Выбор запоминается в браузере посетителя.

## Правила вёрстки

HTML собирается генераторами, поэтому **править файлы в `docs/*.html` бесполезно** —
следующая сборка их перезапишет. Разметку меняем в `*.py`, стили — в `docs/style.css`,
после чего прогоняем `python rebuild_pages.py`.
