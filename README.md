# Old Picture Art

Статический сайт [oldpictureart.ru](https://oldpictureart.ru/): галерея живописи,
посещения музеев, карта собраний, афиша выставок, квиз и хронология.
Python генерирует страницы в `docs/`; GitHub Pages публикует эту папку.

## Быстрая сборка без Telegram и сети

Из корня репозитория, с Python 3.12:

```bash
python -m pip install -r requirements.txt
python rebuild_pages.py --offline
```

Команда читает сохранённые JSON, обновляет `docs/`, не делает commit/push.
При ошибке обязательного генератора завершается с ненулевым кодом.
Для просмотра можно открыть `docs/index.html` в браузере.

## Получение новых постов

`python build_site.py` подключается к Telegram, обновляет данные и страницы,
автоматически коммитит допустимые изменения исходников и контента, делает push
и уведомляет IndexNow. Тесты запускаются на GitHub, а не внутри этой команды.
Перед запуском просмотрите свои незакоммиченные изменения.

Нужен локальный `.env` с `API_ID`, `API_HASH` и `PHONE`. Файлы сессии и `.env`
не должны попадать в Git. `python build_site.py --no-push` отключает Git и
IndexNow, но продолжает обращаться к Telegram и настроенному хранилищу.
Для перечитывания исправленного поста: `python build_site.py --refresh 1234`.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
npm ci
npx playwright install chromium
python rebuild_pages.py --offline
npm test
```

`npm test` запускает все `test_*.py` и `test_*.js` из корня и `tests/`.
Переменная `PYTHON` позволяет указать интерпретатор виртуального окружения,
`CHROME_PATH` — установленный Chromium. Тесты идут также при push и pull request.
Описание сценариев: [tests/README.md](tests/README.md).

## Основные файлы

| Файл или каталог | Назначение |
|---|---|
| `build_site.py` | Получение постов и автоматическая публикация |
| `rebuild_pages.py` | Пересборка из сохранённых данных без Telegram |
| `sitebuild/`, `site_common.py` | Разбор данных, HTML и общий JavaScript |
| `generate_map.py`, `generate_quiz.py`, `generate_timeline.py` | Генераторы разделов |
| `posts_meta.json`, `visits_meta.json` | Основные данные картин и посещений |
| `processed_ids.json` | Уже обработанные сообщения; нужен в Git |
| `afisha.json`, `afisha_archive.json` | Действующие и архивные выставки |
| `museum_overrides.json` | Проверенные адреса, сайты и координаты музеев |
| `museum_coordinates.json`, `afisha_places.json` | Кэши координат для офлайн-сборки |
| `artist_info.json`, `artist_schools.json`, `image_sizes.json` | Данные и кэши сборки |
| `docs/` | Публикуемые страницы, изображения, стили и локальные библиотеки |
| `cloud/auth/` | Облачная функция входа и синхронизации избранного |

`docs/*.html` генерируются: исправляйте Python-генератор, затем пересобирайте.
`docs/style.css` — рабочий исходник стилей. `opa-ui.js` и `docs/opa-ui.js` должны
совпадать. Перенаправления со старых URL, миниатюры, изображения для лупы и
карточки ссылок используются сайтом и не являются мусором.

## Афиша и карта

Данные афиши редактируются в JSON; схема проверяется тестами. Окончание выставки
учитывается браузером по дате. Для исправления метки используйте точный ключ
музея в `museum_overrides.json` с полями `address`, `site`, `lat`, `lon`,
`city`, `country`, затем запустите `python rebuild_pages.py --offline`.
`python generate_map.py --check` показывает сомнительные метки.

Изменения афиши в `main` запускают отдельный workflow пересборки и публикации.
Обычная публикация Pages и workflow проверок независимы: красные тесты сами по
себе не блокируют публикацию из `main`. Перед слиянием проверяйте Actions.
