# Исправления Old Picture Art: безопасная сборка, этап 1

Подготовлено 29 октября 2026. Это ZIP с полными заменяемыми файлами,
а не копия всего репозитория. В GitHub ничего не записано.

Проверены актуальные файлы main через GitHub connector:

## Состав
- build_site.py: полная замена сценария сборки с сохранением публичных импортов.
- sitebuild/text.py: полная замена, прежние имена функций и формат результатов.
- sitebuild/safety.py: новый модуль сохранения и публикации.
- tests/test_safety.py: 15 изолированных регрессионных тестов.
- TEST_RESULTS.txt: фактический результат локального запуска этих тестов.

## Что изменено
1. JSON пишется во временный файл в той же директории и заменяется os.replace.
   Перед заменой существующего корректного JSON сохраняется предыдущая версия
   в <имя>.bak. При ошибке сериализации/замены исходник не обнуляется.
   Поврежденный старый JSON не перезаписывается: требуется ручное восстановление.
2. Ошибки генерации квиза и хронологии прерывают основной build_site.py.
3. Ошибки основного сценария дают exit code 1; Ctrl+C — 130.
4. Telegram отключается через finally при исключениях после подключения.
5. --no-push: сборка без git add/commit/push и без IndexNow.
   Это НЕ офлайн-режим: Telegram и облачное хранилище работают как прежде.
6. Перед публикацией запускаются tests/test_safety.py и существующий tests/run.js.
7. Нет git add .: добавляются docs/ и явный перечень генерируемых JSON.
   .bak/.tmp/.env/.session исключены. При непустом Git index или измененных
   отслеживаемых исходниках публикация останавливается. Исходники коммитят отдельно.
   Все Git-команды проверяются. Повторный запуск пробует push даже без новых изменений.
8. Словарь материалов не перезаписывается, если содержимое не изменилось.
   Автоматическое обучение словаря оставлено ради совместимости.

## Установка (сначала в отдельной ветке или копии проекта)
1. Сделайте резервную копию проекта и JSON-баз.
2. Проверьте git status. Сохраните свои незавершенные правки отдельно.
3. Распакуйте файлы из ZIP в корень существующего репозитория с заменой,
   сохранив директории sitebuild/ и tests/. Не заменяйте проект целиком.
4. Из корня проекта выполните:

   python tests/test_safety.py
   python rebuild_pages.py --offline
   node tests/run.js

   Для локальной полной сборки с Telegram, но без отправки в GitHub:

   python build_site.py --no-push

5. После проверки закоммитьте изменения исходников отдельно (без .bak и секретов):

   git add build_site.py sitebuild/text.py sitebuild/safety.py tests/test_safety.py
   git commit -m "Make site build and JSON writes safer"

6. Обычный python build_site.py затем проверяет результат и публикует разрешенные
   сгенерированные файлы. Нужны Node.js, зависимости npm и Chromium Playwright,
   как для прежнего tests/run.js. Если они не установлены, публикация остановится.
   Отправки в GitHub при подготовке этого архива НЕ выполнялись.

Рекомендуется добавить *.bak и временные .*.tmp в локальный .gitignore.
Сами файлы .bak уже исключены из автоматической публикации.

## Границы и оставшаяся работа
Это этап 1, а НЕ реализация всех пунктов ревью.
- Облачный cloud/auth/index.py, лимит избранного, проверка ID, пакетный YDB,
  рейтинг и инвалидация кэша НЕ менялись: нужны интеграционные проверки YDB.
- Перевод GitHub Pages на деплой проверенного артефакта НЕ сделан.
  При ручном push из другого инструмента workflow по-прежнему не блокирует Pages.
- Полный отказ от побочных эффектов парсера и кэш словаря НЕ реализованы.
- Атомарность относится к отдельному JSON, не к набору файлов и не ко всей сборке.
- Изменения rebuild_pages.py не вносились. Его собственную обработку ошибок
  и subprocess нужно проверять отдельно.
- Сбой сборки может оставить локально частично обновленные HTML; авто-push
  в этом запуске не произойдет, но перед ручной публикацией нужна пересборка.
- Ранние ошибки импорта зависимостей остаются обычными Python-ошибками;
  автоматическая установка зависимостей по-прежнему не исправляет импорт,
  если пакет отсутствует до загрузки модулей.
- При неудачном push коммит остается локальным. Следующий успешный build
  повторит push. Список IndexNow включает только изменения текущего запуска.
- Нет блокировки параллельных сборок: запускайте только один процесс на checkout.
- Полный сайт, Telegram, существующий Playwright-набор и облако в среде
  подготовки архива НЕ запускались. Проверен синтаксис четырех Python-файлов
  и выполнены 15 новых изолированных тестов; Git-тесты используют временные
  локальные репозитории и подменяют push, сетевых отправок нет.
