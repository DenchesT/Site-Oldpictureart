# Вход через Яндекс ID и VK ID — как завести

Вход на сайте теперь через **Яндекс ID** и **VK ID**, а отмеченные картины
вошедших хранит маленькая функция в **Yandex Cloud** (код — `cloud/auth/`).
Firebase больше не нужен.

Пока в `site_common.py` пустые `AUTH_API_URL`, `YANDEX_CLIENT_ID` и
`VK_CLIENT_ID`, кнопки «Войти» на сайте нет, а на странице
«Конфиденциальность» нет раздела про аккаунты — отметки работают в
браузере, как раньше. Всё включается, когда вы впишете эти три строки.

Займёт около часа. Порядок важен: сначала приложения, потом облако.

---

## 1. Приложение в Яндекс ID (10 минут)

1. Откройте **https://oauth.yandex.ru** → «Создать приложение».
2. Название: *Old Picture Art*. Платформа: **Веб-сервисы**.
3. **Redirect URI:** `https://oldpictureart.ru/auth.html`
4. **Доступ к данным:** только «Доступ к логину, имени и фамилии, полу»
   (`login:info`). Почту и телефон не отмечайте — сайту они не нужны.
5. Сохраните. Выпишите **ClientID** и **Client secret**.
   - ClientID — публичный, он пойдёт в `site_common.py`.
   - Client secret — **секрет**, он пойдёт только в функцию в облаке
     (шаг 4). В репозиторий его не кладите.

## 2. Приложение в VK ID (10 минут)

1. Откройте **https://id.vk.ru** → «Мои приложения» (кабинет для бизнеса)
   → «Добавить приложение». Тип — **Web**.
2. **Базовый домен:** `oldpictureart.ru`
3. **Доверенный Redirect URL:** `https://oldpictureart.ru/auth.html`
4. Права: только **имя** (профиль). Почту и телефон не запрашивайте.
5. Выпишите **ID приложения**. Секрет для VK не нужен: сайт входит по PKCE.

## 3. Yandex Cloud: база (15 минут)

1. **https://console.yandex.cloud** → войдите, заведите платёжный аккаунт
   (российская карта). Бесплатного уровня хватит с запасом: 1 млн вызовов
   функции и 1 ГБ базы в месяц — сайту столько не понадобится.
2. **Managed Service for YDB** → «Создать базу данных» → тип **Serverless**,
   имя `opa-likes`. Создайте.
3. Откройте базу → вкладка **Обзор**: выпишите **Эндпоинт**
   (`grpcs://ydb.serverless.yandexcloud.net:2135`) и **Базу данных**
   (`/ru-central1/b1g…/etn…`).
4. Вкладка **Навигация** → «Новый SQL-запрос» → вставьте и выполните:

   ```sql
   CREATE TABLE likes (
     user_id Utf8,
     post_id Utf8,
     created_at Timestamp,
     PRIMARY KEY (user_id, post_id)
   );
   ```

## 4. Yandex Cloud: функция (20 минут)

1. **Identity and Access Management** → «Создать сервисный аккаунт»,
   имя `opa-auth`, роль **`ydb.editor`**.
2. **Cloud Functions** → «Создать функцию», имя `opa-auth`.
   - «Сделать публичной» — **включить** (сайт вызывает её из браузера).
3. «Редактор» → среда **Python 3.12** → способ «Редактор кода»:
   - создайте файл `index.py` и вставьте содержимое `cloud/auth/index.py`;
   - создайте файл `requirements.txt` с одной строкой `ydb>=3.18`.
   - **Точка входа:** `index.handler`. **Таймаут:** 10 с. **Память:** 128 МБ.
   - **Сервисный аккаунт:** `opa-auth`.
   - **Переменные окружения:**

     | Имя | Значение |
     |---|---|
     | `SESSION_SECRET` | 40+ случайных знаков (ниже — как получить) |
     | `ALLOWED_ORIGINS` | `https://oldpictureart.ru` |
     | `REDIRECT_URI` | `https://oldpictureart.ru/auth.html` |
     | `YANDEX_CLIENT_ID` | ClientID из шага 1 |
     | `YANDEX_CLIENT_SECRET` | Client secret из шага 1 |
     | `VK_CLIENT_ID` | ID приложения из шага 2 |
     | `YDB_ENDPOINT` | эндпоинт из шага 3 |
     | `YDB_DATABASE` | путь базы из шага 3 |

     Случайную строку для `SESSION_SECRET` проще всего получить командой
     `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
     Не меняйте её без нужды: смена разлогинит всех.
4. «Сохранить изменения». Дождитесь, пока версия соберётся.
5. **Проверка.** Вкладка «Тестирование» → вставьте во входные данные
   ```json
   {"httpMethod": "POST", "body": "{\"action\": \"ping\"}"}
   ```
   и нажмите «Запустить тест». В ответе должно быть `"db": true`.
   Если `"db": false` — у сервисного аккаунта нет роли `ydb.editor` или
   переменные `YDB_…` вписаны с опечаткой; подробности — во вкладке «Логи».
6. На вкладке «Обзор» скопируйте **ссылку для вызова**:
   `https://functions.yandexcloud.net/d4e…`

## 5. Сайт (5 минут)

В `site_common.py`:

```python
AUTH_API_URL = "https://functions.yandexcloud.net/d4e…"   # из шага 4
YANDEX_CLIENT_ID = "…"                                     # из шага 1
VK_CLIENT_ID = "…"                                         # из шага 2
```

Затем `python rebuild_pages.py` и push. На странице любой картины появится
«Войти», а на странице «Конфиденциальность» — раздел про аккаунты.

Можно завести только один способ: пустой `VK_CLIENT_ID` — кнопки VK не
будет, и наоборот.

---

## Что осталось от Firebase

- Удалите из репозитория `docs/firebase-config.js` и `FIRESTORE.md` — они
  больше не используются.
- В консоли Firebase проект можно удалить. Отметки, сохранённые там через
  прежний вход, автоматически не переедут: это другие аккаунты. Отметки из
  браузера перенесутся в новый аккаунт при первом входе сами.

## Если что-то не работает

- **«Запрос не с сайта» (403)** — в `ALLOWED_ORIGINS` не тот адрес
  (без `/` в конце, с `https://`).
- **«Яндекс не подтвердил вход»** — не совпадает Client secret или Redirect
  URI в приложении Яндекса.
- **«VK не подтвердил вход»** — Redirect URL в VK ID не совпадает с
  `REDIRECT_URI` в функции буква в букву.
- **Вход проходит, отметки не сохраняются** — проверьте `ping` (шаг 4.5).
- Все ошибки функции видны в Cloud Functions → `opa-auth` → «Логи».

Проверки на своём компьютере: `node tests/run.js` — среди них
`test_auth_function.py` (функция без облака) и `test_login.js` (весь путь
входа в браузере с подставными Яндексом и VK).
