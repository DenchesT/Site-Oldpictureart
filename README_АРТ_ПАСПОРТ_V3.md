# Old Picture Art — Арт-паспорт v3

Обновление для уже установленного **арт-паспорта с Yandex Cloud/YDB** в репозитории `DenchesT/Site-Oldpictureart`. Сохранённые данные пользователей и таблицы `likes`/`passport` не удаляются. В GitHub ничего автоматически не отправляется.

## Какие изменения включены

**По вашему списку:**

2. **Дневник музеев:** отдельная запись на каждое посещение, дата, название выставки, впечатления, повторные визиты, изменение и удаление.
3. **Визуальные коллекции:** обложка из картины, описание, сетка миниатюр, ручная сортировка, добавление и удаление.
4. **Статус синхронизации:** «Гость», «Синхронизация», «Сохранено в облаке», «Ошибка», время последней успешной синхронизации, количество ожидающих операций, ручной повтор.
5. **Добавление картины без перехода:** кнопка «В мою коллекцию» открывает список коллекций прямо на странице картины. В самом паспорте — поисковый выбор с миниатюрами.
6. **Выставки:** отдельно «Хочу посетить», «Посетил» (дата и заметка), «Избранное» (существующие звёздочки афиши остаются отдельными).
7. **Карта моих музеев:** отмеченные места на Leaflet/OpenStreetMap, список для мест без точных координат; частные коллекции не добавляются как посещаемые музеи.
8. **Хронология:** посещения, выставки и встречи с оригиналами, группировка по годам, запись оригинала с датой, музеем и впечатлением.
9. **Статистика:** посещения по годам, города, страны, художники и века среди понравившихся произведений.
10. **Диалоговые окна сайта:** редактирование и подтверждения без `prompt()` и `confirm()`.

**Исправления:**

1. Содержимое коллекций хранится **по одной записи на каждую картину** (`collection_work|...`). Поэтому добавление разных картин в одну коллекцию с двух устройств больше не заменяет целый JSON одной копией. Порядок хранится индивидуально для каждого элемента. Если два устройства меняют **одну и ту же картину одновременно**, последнее применённое сервером изменение остаётся победителем — абсолютного бесконфликтного CRDT здесь нет.
2. При импорте и обновлении каталога исчезнувшие из него произведения, художники, музеи и выставки **не удаляются из паспорта**. Они показываются как архивные записи.
3. Для художников и музеев — постоянные `a_...`/`m_...` ID из отслеживаемого файла `passport_registry.json`, а не строки названий. Старые отметки по имени переносятся при первом открытии паспорта и синхронизации. При переименовании сущности нужно присвоить новому названию **старый ID в `passport_registry.json`**, чтобы не создать нового человека/музей по ошибке.
4. Мобильный поиск обновляет **только список результатов** и не пересоздаёт поле ввода на каждом символе, чтобы не терять фокус и не дёргать клавиатуру.

## Установка (без GitHub push)

**Перед началом:** убедитесь, что предыдущий пакет Art Passport Cloud Sync установлен и что в YDB уже есть таблица `passport`. Если вы пользуетесь паспортом, сделайте на сайте **«Экспорт JSON»** как дополнительную личную резервную копию.

1. Распакуйте ZIP **прямо в корень** проекта `D:\Code\oldpictureart_site`. Внутри новая папка `upgrade_payload` содержит подготовленные версии файлов, но ещё **не заменяет** файлы сайта. Установщик сначала проверяет совместимость и создаёт резервную копию.

2. В PowerShell из корня проекта выполните:

   ```powershell
   python apply_passport_upgrade_v3.py --check
   ```

   Должно вывести `OK: project compatible`. Если ошибка, **не** выполняйте `--apply`: пришлите её текст; установщик проверяет ожидаемую структуру текущей ветки.

3. Примените:

   ```powershell
   python apply_passport_upgrade_v3.py --apply
   ```

   Скрипт запишет 10 изменённых файлов и сохранит предыдущие версии рядом с проектом в папке вида `oldpictureart_site_backup_passport_v3_...`. Секреты, база и данные пользователей не затрагиваются.

4. Проверьте:

   ```powershell
   node tests/test_passport_actions.js
   node tests/test_passport_cloud.js
   node tests/test_passport_v3_sync.js
   python -m unittest discover -s tests -p "test_*v3.py"
   python rebuild_pages.py --offline
   git status --short
   ```

   Если в вашем проекте другие тесты, запустите и их (`node tests/run.js`). После пересборки **должен появиться `passport_registry.json` в корне** — его нужно отслеживать в Git, чтобы ID не менялись от сборки к сборке. Сборка также обновит `docs/passport.html` и страницы картин/художников/музеев.

5. **Обязательное обновление Cloud Function.** Откройте Yandex Cloud → Cloud Functions → существующая `opa-auth` → «Редактор». Замените содержимое **только `index.py`** на локальный `cloud/auth/index.py` после выполнения установщика. Сохраните прежние `requirements.txt`, Python runtime, точку входа `index.handler`, сервисный аккаунт, переменные `SESSION_SECRET`, `YANDEX_CLIENT_ID`, `VK_CLIENT_ID`, `YDB_ENDPOINT`, `YDB_DATABASE`. Затем создайте новую версию функции. **Не меняйте URL функции на сайте.**

6. В тестировании Cloud Function выполните `ping`, который должен вернуть `{"ok":true,"db":true}`. Проверка `passport_sync` **без токена** должна по-прежнему вернуть `401` — это ожидаемо, но не доказывает сохранение данных. Для полной проверки нужен вход через тот же аккаунт на двух устройствах.

7. После успешной проверки можете **сами** зафиксировать и отправить изменения в GitHub. Прежде чем использовать `git add .`, посмотрите `git status --short`: не включайте `.env`, бэкапы и токены.

**Новая таблица YDB не требуется.** Продолжаем использовать существующие `opa-likes` → `likes` и `passport`.

## Проверка на двух устройствах

1. На компьютере откройте `passport.html` и войдите в аккаунт через Яндекс ID/VK ID. Отметьте музей, добавьте визит с датой, создайте коллекцию и добавьте в неё картину.
2. Убедитесь, что статус **«Данные сохранены в облаке»**.
3. На телефоне войдите через **тот же способ и тот же аккаунт**, откройте паспорт. Должны появиться все данные.
4. Добавьте другую картину в **ту же коллекцию** на телефоне. После обновления на компьютере обе картины должны остаться.
5. Отключите сеть на телефоне, измените запись, затем включите сеть — очередь отправится при возврате на страницу.
6. Проверьте, что архивные данные остаются при экспорте/импорте JSON.

## Что в архиве

- `apply_passport_upgrade_v3.py` — проверка, резервная копия и установка без коммитов.
- `upgrade_payload/docs/passport-actions.js` — локальное хранилище, синхронизация, миграция и добавление в коллекции на страницах картин.
- `upgrade_payload/docs/passport.js` — интерфейс дневника, музеев, коллекций, выставок, карты, хронологии и статистики.
- `upgrade_payload/docs/passport.css` — адаптивный дизайн.
- `upgrade_payload/sitebuild/passport.py` — HTML-генератор паспорта и данные карты.
- `upgrade_payload/sitebuild/passport_ids.py` — постоянные ID и реестр названий.
- `tests/test_passport_v3_sync.js` и `tests/test_*v3.py` — тесты.
- `tests/browser_smoke_passport_v3.py` — отдельный браузерный smoke-тест (нужен установленный Playwright/Chromium), необязателен для установки.

## Ограничения

- Реальную YDB и браузер вашего аккаунта проверить удалённо невозможно: тесты работают на моделях двух устройств и базе-имитаторе. После установки нужен ручной тест на сайте.
- Для карты нужна загрузка картографической подложки OpenStreetMap. Если сеть её блокирует, личные музеи остаются видимыми в текстовом списке.
- Статистика веков считается приближённо по году создания отмеченных картин, не по художественным направлениям.
- Изменения в **одной и той же** записи с разных устройств одновременно разрешаются по последней записи; изменения **разных картин** в коллекции хранятся раздельно.
- При переименовании музея/художника вручную сопоставьте новое название со старым ID в `passport_registry.json`; автоматического распознавания тождественности двух имён без внешнего идентификатора нет.

## Откат

Установщик печатает путь к резервной копии. Чтобы откатить код, восстановите старые файлы из неё и пересоберите `python rebuild_pages.py --offline`. Перед откатом **экспортируйте пользовательские данные**: старая версия не умеет отображать новые дневники/статусы, хотя записи в YDB останутся.
