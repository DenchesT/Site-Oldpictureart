# Old Picture Art — арт-паспорт v3.1: адаптивность, поиск, карта, CI

Обновление подготовлено для уже установленного **арт-паспорта v3** в репозитории `DenchesT/Site-Oldpictureart`. Все пути внутри ZIP отсчитываются от корня репозитория. Дополнительную папку верхнего уровня создавать не нужно.

## Что исправлено

- На телефонах длинные названия музеев отображаются в собственной строке; кнопки **«Отмечено» / «В дневник»** размещаются снизу, не сдавливают название.
- Для карточек оригиналов и коллекций единая сетка, предсказуемая высота изображений и текста, нормальный перенос слов и кнопок; адаптивность для 320–1280 px и больше.
- В модальных формах поиск по **названию картины, художнику или музею** и по **названию/месту музея**. После ввода отображается не весь длинный системный список, а до 45 найденных вариантов. Если вариант единственный, он выбирается автоматически.
- На вкладке «Оригиналы» также есть поиск по уже отмеченным картинам (название/художник/музей/год), пагинация по 36 карточек.
- Календарь унифицирован со стилем сайта (собственная месячная сетка, кнопки «Сегодня»/«Очистить»); можно ввести дату как `ДД.ММ.ГГГГ` вручную. Перед отправкой дата переводится в привычный для данных формат `YYYY-MM-DD`.
- Диалог учитывает `visualViewport` и скроллит активное поле внутрь видимой части, когда на телефоне открывается клавиатура. Кнопка сохранения закрепляется внизу прокручиваемой формы.
- Карта личных музеев пользуется **тем же `OPA_MAP`**, что и основная «Карта собраний»: те же подложки, запоминание выбранного слоя, тёмное оформление, учёт ошибки Яндекс-тайлов, собственные маркеры-этикетки и группировка близких меток. Есть режим «На весь экран». Подключаются локальные `map-config.js` и `vendor/leaflet.markercluster` из проекта.
- Три падающих теста CI: добавлены пути импорта при прямом запуске `test_passport.py` и `test_passport_sync_installer.py`; исправлен `__all__` в `sitebuild/passport_ids.py`; удалены два неиспользуемых импорта.

## Установка

**Внимание:** распаковка с перезаписью заменит перечисленные файлы. Проверьте `git status --short` и сделайте резервную копию своих незакоммиченных правок **до** распаковки. Ничего не отправляется в GitHub автоматически.

1. Убедитесь, что арт-паспорт v3 установлен.
2. Распакуйте ZIP с сохранением структуры `docs/`, `sitebuild/`, `tests/` **в корень** `D:\Code\oldpictureart_site` (не в отдельную вложенную папку).
3. В PowerShell из корня проекта:

```powershell
cd D:\Code\oldpictureart_site
node --check docs/passport.js
node --check docs/passport-actions.js
node tests/test_passport_actions.js
node tests/test_passport_cloud.js
node tests/test_passport_v3_sync.js
python tests/test_passport.py
python tests/test_passport_sync_installer.py
python tests/test_structure.py
python rebuild_pages.py --offline
git diff --check
git status --short
```

4. Убедитесь, что обновлён `docs/passport.html` и что рядом доступны `docs/passport.css`, `docs/passport.js`, `docs/passport-actions.js`. После проверки можете самостоятельно закоммитить и отправить изменения в GitHub.
5. После публикации на телефоне обновите страницу без кэша либо закройте/откройте браузер, чтобы подтянуть изменившиеся CSS/JS.

## Облако / пользовательские данные

**YDB и Cloud Function `opa-auth` менять не требуется**: формат и схема синхронизации v3 остаются прежними. Файлы не добавляют внешних сервисов. Все локальные данные и облачные таблицы сохраняются.

- `node --check` — оба JavaScript-файла.
- Три существующих набора Node-тестов: `test_passport_actions.js`, `test_passport_cloud.js`, `test_passport_v3_sync.js` — пройдены.
- Два инсталляционных Python-теста (в изолированном рабочем наборе) — пройдены.
- Playwright/Chromium без интернета: desktop 1280 px, mobile 390 px — поиск, формирование посещения и коллекции, обработка даты, открытие формы, вёрстка музейных строк и проверка отсутствия горизонтального переполнения — пройдены.

Полные проверки GitHub Actions будут доступны только после следующего push; ожидаемые причины последних трёх сбоев устранены, но прохождение всех тестов в полном окружении репозитория нужно подтвердить отдельным запуском.
