# Old Picture Art — исправления кода (29.10.2026)

**Репозиторий:** <https://github.com/DenchesT/Site-Oldpictureart>

Это **накладное обновление исходников**, а не полный архив сайта: изображения,
генерируемые HTML-страницы (`docs/`), данные и учётные данные не включены.
ZIP раскладывается поверх существующего клона проекта. Никаких сетевых вызовов,
публикаций, изменений метаданных картин или операций с Telegram этот архив не делает.

## Что исправлено

1. `sitebuild/indexnow.py`
   - Все URL отправляются батчами максимум по 10 000, без молчаливой потери хвоста.
   - Успех означает принятие **каждой** пачки **каждым** настроенным endpoint.
     При частичном сбое список остаётся на повторную отправку.
   - Очередь `indexnow_pending.json` сохраняется атомарно.
   - XML-сущности в `sitemap.xml` распаковываются перед отправкой.
2. `sitebuild/links.py`
   - Только HTTP(S) URL с допустимым хостом попадают в HTML-ссылки.
   - Исключены `javascript:`, `data:`, `file:`, `//host` и управляющие символы.
   - Ссылки очищаются от параметров слежения, дубликаты убираются.
   - Небезопасная ссылка не ломает страницу: остаётся экранированная подпись.
3. `sitebuild/safety.py`
   - Расширены запреты для файлов автоматического коммита: `.npmrc`, `.netrc`,
     `.ssh`, `.aws`, ключи, `credentials.json`, `secrets.json`, базы SQLite и т. п.
   - Проверяются также пути-симлинки, уже помещённые в git index.
   - Публичные функции и формат JSON остались прежними.
4. `sitebuild/telegram.py` — проверка `mime_type` у изображений не падает
   на документах без указанного MIME-типа (отдельный проверяемый патч).
5. `build_site.py` — устранение дублирования (отдельная безопасная правка скриптом):
   - Один `_image_comments` вместо двух почти одинаковых проходов комментариев.
   - Не падает, если у документа Telegram отсутствует `mime_type`.
6. `tests/test_quality_update.py` — **11 офлайн-тестов** новых сценариев.
7. `.github/workflows/tests.yml` — тесты обновления включены в CI.

## Установка (Windows / VS Code)

1. Сделайте **резервную копию** или коммит исходного состояния. Убедитесь, что нет
   чужих незакоммиченных изменений: `git status`.
2. Распакуйте ZIP **в корень клона** `Site-Oldpictureart`, с сохранением папок
   и подтверждением замены файлов. ZIP не содержит `posts_meta.json`, `docs/`
   или `.env`.
3. В терминале из корня выполните:

   ```bash
   python apply_build_site_refactor.py
   python apply_telegram_fix.py
   python tests/test_quality_update.py
   python tests/test_safety.py
   git diff --check
   git diff
   ```

   Скрипт рефакторинга проверяет наличие ожидаемых фрагментов, прекращает работу
   без изменений при несовпадении и перед правкой сохраняет
   `build_site.py.before-quality-update.bak` (Git не должен публиковать `.bak`).
   Вторая правка аналогично создаёт `sitebuild/telegram.py.before-quality-update.bak`.
4. При успешном результате **не запускать сразу** `build_site.py`, если не хотите
   реального Telegram-подключения и автоматического `git push`. Для проверки
   страниц можно выполнить `python rebuild_pages.py --offline` (создаёт файлы
   в `docs/`, поэтому сначала сделайте резервную копию/коммит).
5. Проверив `git diff`, самостоятельно сделайте коммит и отправьте изменения.

## Пределы проверки

- Просмотрены дерево репозитория, основной Python-код, связи модулей, некоторые
  тесты, а также ключевые участки JavaScript в Python-генераторах страниц.
- В этой среде запущены **11 новых изолированных тестов**: 11/11 пройдены.
  Они проверены на исходниках обновления со служебными заглушками конфигурации.
- **Не** запускались полная сборка из Telegram, браузерные Playwright-тесты,
  GitHub Actions, реальные IndexNow-запросы и полный набор тестов исходного
  репозитория: здесь отсутствует полный рабочий клон и реальные данные.
- В проекте есть крупные генераторы (`site_common.py`, `generate_map.py`,
  `sitebuild/afisha.py`, `sitebuild/posts.py`). Дальнейшую декомпозицию их
  целесообразно выполнять небольшими отдельными изменениями с полноценными
  браузерными регрессиями; механически переписывать их целиком рискованно.
- В `sitebuild/config.py` сейчас присутствуют настройки MTProxy прямо в коде;
  при возможности лучше получать их из переменных окружения/непубличной
  конфигурации, а используемые публично значения пересмотреть.
- `cloud/auth/index.py` и браузерная авторизация требуют отдельного аудита
  OAuth, хранения сеансов и защиты от XSS; здесь авторизация не менялась.

## Откат

Все изменения ограничены перечисленными файлами. Если нужно отменить:

```bash
git restore sitebuild/indexnow.py sitebuild/links.py sitebuild/safety.py \
    .github/workflows/tests.yml build_site.py sitebuild/telegram.py
```

Новые `tests/test_quality_update.py`, `apply_build_site_refactor.py`,
`apply_telegram_fix.py` и этот
README можно удалить вручную. Не делайте `git restore`, если в тех же файлах
были нужные незакоммиченные правки: сначала сохраните их отдельно.
