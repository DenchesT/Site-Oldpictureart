# Тесты только в GitHub Actions

Это исправление предыдущего архива. Распакуйте в корень существующего проекта
с заменой файлов, сохраняя папки. Полные файлы, не патч и не установщик.

Изменения:
- build_site.py: обычный запуск собирает сайт и отправляет результат, но НЕ
  вызывает tests/run.js, test_safety.py, npm, npx или установку браузера.
- tests/test_safety.py: обновлена проверка нового поведения; прежний тест,
  требовавший локальный запуск тестов, заменен. Тесты не удалены из CI.
- sitebuild/safety.py: сохранены атомарная запись, безопасный список файлов
  публикации; добавлен __all__ для совместимости с test_structure.py.
- .github/workflows/tests.yml: Python-проверки и общий набор выполняются на
  GitHub при push / pull_request / ручном запуске. Не вызывает build_site.py,
  не подключается к Telegram, не делает обратных коммитов.

Остальные файлы проекта НЕ заменяются, включая ранее исправленный
sitebuild/text.py и ваши package.json / package-lock.json с новым Playwright.

Установка:
1. Сохраните открытые файлы VS Code, закройте вкладки этих четырех файлов,
   сделайте резервную копию, затем распакуйте архив в корень проекта.
2. Разово сохраните изменения исходников в Git. Проверьте git status и diff,
   убедитесь, что в индексе нет посторонних изменений или секретов.
   Эти команды включают также предыдущие исправления из переписки:

   git add build_site.py sitebuild/safety.py sitebuild/text.py tests/test_safety.py .github/workflows/tests.yml package.json package-lock.json
   git commit -m "Run automated tests only in GitHub Actions"
   git push

   Если у вас есть другие измененные отслеживаемые исходники, сохраните их
   отдельно. Автоматическая публикация намеренно не коммитит их сама.
3. Дальше запускайте как обычно из корня проекта:

   python build_site.py

   Локального прогона тестов не будет. --no-push по-прежнему отключает отправку.
   Проверка наличия Python-зависимостей и предупреждения о данных остаются:
   это рабочие этапы сборки, а не запуск тестового набора.

На компьютере Node.js и Chromium для обычного build_site.py больше не нужны.
Они останутся нужны только если вы вручную решите запустить браузерные тесты.

Границы:
- Две известные ошибки данных карты/частных собраний НЕ исправляются и НЕ
  скрываются. Их покажет GitHub Actions; локальную сборку тесты не блокируют.
- Настройки Pages не меняются. Этот workflow проверяет сайт, но не реализует
  запрет публикации Pages при красных тестах. Это отдельная задача.
- Автоматическая отправка может остановиться из-за реальной ошибки генерации,
  Git, сети или незакоммиченных исходников. Это не запуск локальных тестов.
- Автоматические тесты не запускаются при обычной сборке, однако остаются
  доступными для ручного запуска.
- Полный сайт, Telegram, YDB, Playwright и GitHub Actions здесь не запускались.
  В среде подготовки пройдены 16 изолированных регрессионных тестов, включая
  отсутствие запуска локальных тестов в push_to_github. Git push подменялся;
  ни один запрос на изменение GitHub не выполнялся.
